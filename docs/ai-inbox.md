# 把 AI 对话放进房间

内容先进入房主的私有收件箱。发布到笔记本必须由登录后的房主明确操作；AI 投递接口不能直接发布，也不能改写既有内容。

## 普通 GPT / Gemini 对话

在想保留的一段对话后使用下面的整理提示词。审阅结果，保存为 `.md` 文件，或直接复制正文。在房间登录 → 收件箱 → 整理一篇 → 导入 Markdown，选择来源并保存草稿。阅读预览，修改后再点击“发布到笔记本”。

```text
请把刚才这段对话整理成我的个人笔记，输出 Markdown。
第一行是一个简短的一级标题，之后是正文，不要 YAML frontmatter。

1. 保留我原来的语气、犹豫和不确定，不要替我得出结论。
2. 只把我确实说过或明确认可的感受写成第一人称。
3. 你的推断和建议必须单独标成“AI 的建议”，不能冒充我的想法。
4. 原话用引用块保留，不要把改写后的句子标成原话。
5. 未解决的问题单独列出；不要强行总结成励志或宣传文案。
6. 不要自动包含整段聊天、账号、联系方式或第三人的信息。
7. 如果我的意思不明确，请列出待我确认的句子，不要补写经历。
8. 此稿只用于我的私有收件箱，由我检查后决定是否公开。
```

无论聊天产品是否支持调用外部接口，这条文件导入流程都可用。没有提供真实书目时，书架中的《房间笔记》是明确标注的原创阅读样稿。

## 支持 HTTP 工具的 AI 客户端

仓库提供 Supabase Edge Function `submit-thought` 和 `docs/ai-inbox.openapi.json`。

1. 在 Supabase Edge Functions 的 Secrets 中设置高熵的 `ROOM_INGEST_TOKEN`（至少 32 个字符）。它只用于这个草稿入口，不是数据库 Service Role Key。
2. 部署：`supabase functions deploy submit-thought --project-ref YOUR_PROJECT`。`supabase/config.toml` 关闭该函数默认 JWT 校验，函数自身会校验独立的 Bearer token；缺少配置时返回 503，错误 token 返回 401。
3. 把 OpenAPI 文件中的 `YOUR_PROJECT` 替换成真实项目引用。在支持自定义 HTTP 工具的客户端中配置这个接口，并通过其凭据设置保存该 token。不要把 token 写入聊天提示词或仓库。
4. 每篇稿件带一个 UUID `request_id`；网络重试沿用同一个 UUID，避免重复投递。

例如请求正文：

```json
{
  "request_id": "10000000-0000-4000-8000-000000000001",
  "title": "我还想继续想的问题",
  "body": "## 我的想法\n\n这里是我已确认的整理稿。",
  "source": "gpt"
}
```

即使调用方额外传入 `status: "published"`，服务端也只插入 `draft`。接口不返回数据库密钥或私有笔记列表。普通 GPT/Gemini 聊天是否可以直接调用，取决于所用产品的工具功能；不能假设所有聊天窗口都能自动发送请求。

浏览器中阅读 AI Markdown 时会清理脚本、危险链接与嵌入内容，不加载正文中的远程图片。内容长于 30,000 字或请求超过 64 KiB 会被拒绝。
